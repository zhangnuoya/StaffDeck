# StaffDeck + Codex 同容器部署(XWorker 镜像,源码构建 + 开发热更双模式)

## 目标

把 StaffDeck 后端(FastAPI 5173,含前端 dist)与 Codex CLI 部署进同一个容器,supervisord 统一托管,容器/镜像/卷改名 **xworker** 系列。StaffDeck 本体 100% 由当前仓库源码构建(代码 COPY、前端用本地已构建 dist,不拉取任何 StaffDeck 发布包/镜像),支持「生产部署」与「频繁开发」双模式,数据库全新开始。

架构变化:backend 用现有「本地 CLI」codex 适配器(`backend/app/runtimes/adapters/codex.py`)同容器直接调 `codex exec`,MCP gateway 走 `http://127.0.0.1:5173` 回环,不再依赖 docker exec / host.docker.internal。

## 数据持久化保证(用户最关心)

- `docker build` 只造镜像,不碰运行数据;**recreate 容器不丢数据**,所有状态在卷/bind mount:
  - StaffDeck 数据库(含 WAL):命名卷 `xworker-staffdeck-data`(DATABASE_URL 指向 `/opt/staffdeck/staffdeck-data/skill_agent_loop.db`,ULTRARAG_DATA_DIR 同卷)
  - codex 登录态/配置/会话:`xworker-codex-home`;飞书绑定:`xworker-lark-home`;cc-switch:`xworker-ccswitch-home`;员工工作区:宿主机 bind mount
- 升级流程 `docker compose build && docker compose up -d` 全程保留数据
- 唯一会丢的情况:显式 `down -v`/`docker volume rm`(README 标注警告);卷改名后旧 `ai_emp_codex-*` 卷不自动迁移,README 提供可选卷复制命令(codex 登录态/飞书绑定),或接受重新 login+扫码
- 开发 overlay 模式下数据库同样在命名卷,改代码/重启容器不碰数据

## 依赖获取策略(回应频繁开发)

- 仅第三方 pip 库(fastapi/pydantic 等)在**镜像构建期**从清华 PyPI 下载一次;StaffDeck 本身永不从外部源拉取
- `pyproject.toml` + `uv.lock` 单独镜像层 → 依赖不变时重建秒级,改代码完全不重建
- venv 独立放 `/opt/staffdeck/venv`(不放 backend/.venv),避免开发 overlay 挂载源码时遮蔽
- 通用技能运行时依赖**构建期预装**进 `/opt/staffdeck/runtime-venv`,运行时 `GENERAL_SKILL_RUNTIME_AUTO_INSTALL=false`,运行时不联网装包

## 风险与备注
- Python 3.14 依赖兼容:uv.lock 已含 py3.14 wheel 标记,风险低;个别包失败则基础镜像降 python:3.13-slim
- 宿主机 5173 旧 backend 进程需先停,避免端口冲突
- `.env` 不 COPY 进镜像(含密钥),通过 compose env_file/environment 注入
